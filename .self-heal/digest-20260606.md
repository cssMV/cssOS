## ② 真实 bug + 建议 diff

### A. i18n_leak 误报:语言选择器 endonym 被当成泄漏(风险:低)

**根因.** `#foryou-market-lang-chips` 的按钮文字来自 `populateMarketLangChips()` 的 `l.native`(语言自称名,如 中文/日本語/한국어 — `public/app.market-commerce.js:653`)。语言选择器显示各语言的本族名(endonym)是**标准且正确的 UX**,不是泄漏。`app.i18n-leak-probe.js` 的 `SKIP_CLOSEST` 白名单已收录人名/歌词/字幕/`[data-cjk-ok]` 等合法 CJK 容器,只是漏了语言选择器。

**修复.** 把语言选择器加入 `SKIP_CLOSEST`(已本地 `node -c` 验证通过,随后已复原):

```diff
--- a/public/app.i18n-leak-probe.js
@@ SKIP_CLOSEST
     ".cssos-agent-msg", ".msrc-vision-row", ".person-mv-theme", ".pmv-mv-angle",
-    "#cssos-pmm", "#cssos-agent-panel .body"
+    "#cssos-pmm", "#cssos-agent-panel .body",
+    "#foryou-market-lang-chips", ".cssos-lang-endonyms", "[data-lang-endonym]"
   ].join(",");
```

(附带 `.cssos-lang-endonyms` / `[data-lang-endonym]` 两个通用钩子,便于未来其它语言选择器复用,不必逐个登记 id。)
**风险:低** — 纯诊断脚本,只缩小扫描面,不改任何用户可见 DOM。

### B. i18n_leak 真泄漏:civ 下拉缺映射,回退原始中文(风险:低)

**根因.** `.person-mv-civ-select` 的 option 文字**已**走 `civDisplayName()` 本地化(`public/app.person-mv-panel.js:1929`),但 `CIV_DISPLAY_NAMES` 映射表(`public/app.civ-language-map.js:127`)缺少「中华神话 / 中华佛教神话 / 中华民间」三个分类键。`civDisplayName` 对未知词"原样返回",于是非中文 locale 下这三项以原始中文显示 → 真泄漏。

**修复.** 在 Chinese 区块(`app.civ-language-map.js:142` 之后)补三条:

```diff
--- a/public/app.civ-language-map.js
@@ "近代中国":    "Modern China",
     "近代中国":    "Modern China",
+    "中华神话":    "Chinese Mythology",
+    "中华佛教神话": "Chinese Buddhist Mythology",
+    "中华民间":    "Chinese Folk",
     // Japan
```

**风险:低** — 纯增映射,符合 i18n 铁律(显示英文、value 仍保留原始中文键用于分组/过滤,不影响文明智能联动的母语判定:`中华*` 仍命中 `match:["中华"...] → zh`)。
**建议同步排查:** 还可能有其它未收录的 sub-civ taxonomy(神话/民间/朝代变体)同样漏 —— 上线前可在真实 person 数据里跑一遍 distinct civilization 对照映射表补齐。

### C. i18n_leak 真泄漏:Auto 选项硬编码中文源串(风险:低–中,⚠️邻近红线区)

**根因.** 三个 `<option>` 带了 `data-i18n` 键,但**源文本是中文**("Auto · 智能填充" 等,`public/index.html:1244/1384/1417`),与「English is the single source of truth」铁律相反。W210 翻译管线以英文为源;中文源串在翻译落地前(或键未命中时)直接漏给非中文用户。

**建议修复.** 把源文本改为英文(键不变,管线照常翻译):

```diff
--- a/public/index.html
- <option value="" selected data-i18n="creation.option.vocalGender.auto">Auto · 文明智能填充</option>
+ <option value="" selected data-i18n="creation.option.vocalGender.auto">Auto · Civilization smart-fill</option>
...
- <option value="" selected data-i18n="creation.option.key.auto">Auto · 智能填充</option>
+ <option value="" selected data-i18n="creation.option.key.auto">Auto · Smart-fill</option>
...
- <option value="" selected data-i18n="creation.option.workType.auto">Auto · 智能判断</option>
+ <option value="" selected data-i18n="creation.option.workType.auto">Auto · Smart-detect</option>
```

**风险:低–中。⚠️ 流程红线:** `#creation-key / #creation-work-type / #voice-input` **不在** MUSIC STYLE 硬锁清单(硬锁 = `.creation-tabs`/`.creation-chips`/`#creation-style-input`/`#creation-style-count`),但**物理上紧邻**红线区块。按 W220.A 工作纪律,**上线前需 Jing 显式确认**「可以改这三个 option 的源文本」,严禁顺手碰到周边冻结选择器。建议措辞:*"计划把 #creation-key / #creation-work-type / #voice-input 三个 Auto option 的中文源串改成英文(data-i18n 键不变)。授权?(yes/no)"*

### D. (低优先)占位 ID 漏进 fetch(风险:低)

**现象.** `API 400 /api/works/#__part_3/language-tracks`(8)、`/slideshow`(8)、`/api/works/voice_#/slideshow`(4)—— workId 是未替换的模板占位符(`#__part_3`、`voice_#`)。W588w 已对 `workId="#"` 做 fetch 前拦截,但**多段占位符变体**(`#__part_*`、`voice_#`)未覆盖。
**建议.** 在 works 拉取入口把"含 `#` 的 workId"统一视为占位、fetch 前拒绝(扩展 W588w 的 `cross_file_symbol_defensive_ref` 守卫:`if(/#/.test(workId)) return;`)。需先定位 language-tracks/slideshow 的调用点(下一轮深入)。**风险:低**,但建议单独小波处理,不与 i18n 捆绑。
