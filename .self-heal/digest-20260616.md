## ② 真实 bug — 根因 + 建议 diff + 风险

### Bug A — i18n 探针误报「语言选择器端名」(count 355,#2+#3)

**根因:** `#foryou-market-lang-chips` 的语言筛选胶囊显示各语言的**端名(endonym)**——"中文 / 日本語 / 한국어"——这是**全球通行的正确做法**(Apple/Google 语言选择器皆如此),与 UI locale 无关。源码 `public/app.market-commerce.js:663` `bar.appendChild(mk(l.code, l.native))` 显示 `l.native`,「All」胶囊已正确走 `loginCopy("All","全部")`。但 `app.i18n-leak-probe.js` 扫 `button` 见 CJK 即上报 → **误报**。它常年霸占 digest 第 2/3 名,淹没真泄漏。

**建议 diff** — `public/app.i18n-leak-probe.js`,把语言选择器加入 `SKIP_CLOSEST`(探针已支持 `[data-cjk-ok]` / 容器排除):

```js
  var SKIP_CLOSEST = [
    ".work-card", "[data-work-id]", "[data-person-id]", ".pmv-card", ".person-mv-card",
    ".lyrics", ".karaoke", ".subtitle", ".cssmv-lyrics", "[data-cjk-ok]", "[lang^=zh]",
    ".cssos-agent-msg", ".msrc-vision-row", ".person-mv-theme", ".pmv-mv-angle",
    "#cssos-pmm", "#cssos-agent-panel .body",
+   "#foryou-market-lang-chips"   // 语言选择器合法显示端名(中文/日本語/한국어),非泄漏
  ].join(",");
```

**风险:低。** 纯诊断文件,不改任何用户可见 DOM,只抑制已确认的误报。
**附注:** 若别处还有语言选择器(如 `mv-language-picker`),可一并加;本波只针对 digest 实际命中的选择器,保持范围最小。

### Bug C — 创作/声线选择器硬编码双语「Auto · 中文」源文本(count 63,21×3)

**根因:** `index.html` 三个 `<option>` 的**源文本含中文**,违反「英文是唯一真源,绝不硬编码中文」。它们虽带 `data-i18n` 键,但键的英文源被中文污染,非中文 locale 翻译链拿到的就是中英混排:

- `index.html:1265` `select#voice-input>option` → `Auto · 文明智能填充`
- `index.html:1405` `select#creation-key>option` → `Auto · 智能填充`
- `index.html:1438` `select#creation-work-type>option` → `Auto · 智能判断`

**建议 diff** — `index.html`,源文本改为纯英文(`data-i18n` 键不变,翻译链负责其它语言):

```html
- <option value="" selected data-i18n="creation.option.vocalGender.auto">Auto · 文明智能填充</option>
+ <option value="" selected data-i18n="creation.option.vocalGender.auto">Auto · civilization smart-fill</option>

- <option value="" selected data-i18n="creation.option.key.auto">Auto · 智能填充</option>
+ <option value="" selected data-i18n="creation.option.key.auto">Auto · smart-fill</option>

- <option value="" selected data-i18n="creation.option.workType.auto">Auto · 智能判断</option>
+ <option value="" selected data-i18n="creation.option.workType.auto">Auto · smart-detect</option>
```

**风险:中 — 需 Jing 显式授权后再动。** `#voice-input` / `#creation-key` / `#creation-work-type` 本身**不在** MUSIC STYLE 硬锁的点名清单(硬锁=`.creation-tabs`/`.creation-chips`/`#creation-style-input`/`#creation-style-count`),但它们紧邻创作面板冻结块。按 AI 工作纪律(W220.A),改动创作块附近须先问。另:上线需 `?v` bump,且新英文源会触发 W210 懒翻译重译该键。**本波只起草,不动。**
