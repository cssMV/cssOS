## ② 真实 BUG(根因 + 建议修复 + 风险)

### 🔴 BUG-1 `static_perm_500` — 33 个静态 JS 卡在 600,nginx 500(高危·活跃)
**根因**(只读探针实证):
```
/srv/cssos/current/public/app.advanced-panel-settings-render.js  →  -rw------- (600)
find current/public -maxdepth1 -name '*.js' ! -perm -004  →  33 个文件
```
受影响文件含核心:`app.boot.js`、`app.subscription-panel.js`、`app.watch-media-chrome.js`、
`app.watch-media-overlays.js`、`app.creation-*.js`、`app.context-menu.js`、`app.mv-tier-picker-modal.js` 等。
非世界可读 → nginx(异用户)返回 500 → `nosniff` 拒绝执行 → 对应功能冻结/`Load failed`(直接解释 #6 的相当一部分)。
**注**:i18n 关键文件(`app.civ-language-map.js`/`app.i18n-leak-probe.js`/`app.market-commerce.js`/`app.person-mv-panel.js`)经核**都是 644 正常**,所以本次 i18n 漏键(#2/#3)与本条无关。

**这不是脚本 bug**:`scripts/deploy.sh:87-89`(CSSOS_WAVE_1082)与 `scripts/deploy-express.sh:24,71`
**都已**对 `current/public` 做 `chmod -R a+rX`。33 个 600 文件来自**绕过两个脚本的手工 `rsync`**(改前端后手动同步、漏了 chmod 步)→ 进程问题,代码层防线已存在。

**建议修复(需 Jing 手动·一行,本工具禁止执行)**:
```bash
ssh api-vm 'sudo chmod -R a+rX /srv/cssos/current/public'
```
**预防**:前端 public 改动一律走 `scripts/deploy.sh` 或 `scripts/deploy-express.sh`,**绝不手工 `rsync` public/**(否则又落 600)。
**风险评级:高**(线上多功能冻结中,且复发性问题)。修复动作本身**低风险**(纯放宽读权限)。

### 🔴 BUG-2 `whisperx_worker_down` — 对齐服务 inactive,新字幕全断供(高危·活跃)
**根因**(只读探针实证):
```
curl -m8 http://10.128.0.5:7892/health  →  http_code=000(超时不可达)
systemctl is-active cssos-whisperx-align  →  inactive
```
与记忆铁律 `whisperx_align_hang_blocks_all_subtitles` 吻合:此服务挂 = `resubtitle` 永挂 + **所有新作品没有情绪字幕**(平台招牌功能)。本次是进程 `inactive`(非"假活"挂死),systemctl 未被骗过。

**建议修复(需 Jing 手动,本工具禁止执行)**:
```bash
ssh api-vm 'sudo systemctl restart cssos-whisperx-align && sleep 3 && curl -m8 -o /dev/null -w "%{http_code}\n" http://10.128.0.5:7892/health'
```
**预防**:加一条定时 ping 自愈(记忆 `whisperx_align_hang_blocks_all_subtitles` 早记的待办——给该 unit 配 systemd watchdog 或外部 healthcheck 自动 restart)。
**风险评级:高**(招牌功能断供中)。修复动作**低风险**(重启单一无状态对齐 worker)。
