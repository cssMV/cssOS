## ② 真实 bug + 建议 diff

### 🔴 A. `static_perm_500`(390,今天仍在涨,**最高优先**)— 需人工 root,无我可上线的代码 diff
- **现象**:`static UNREADABLE (600→nginx500→all-keys-leak), auto-chmod FAILED (need root): version.json`。静态文件被写成 `600`,nginx 读不了 → 500 → 自愈层想 chmod 但没 root 权限。
- **根因**:nginx 静态根下某些文件(如 `version.json`)权限 `600`,www-data 读不到。与既往教训一致(`deploy_public_assets_separately.md`:public/ 资产权限/部署链路)。`scripts/deploy-express.sh` 只对后端 `dist/`(`TARGET_DIR`)做了 `sudo chmod -R a+rX`(:71),**public 静态根不在该链路里**,故其权限无人兜底。
- **人工修复(root,交 Jing 执行)**:
  ```
  ssh api-vm 'sudo chmod 644 <STATIC_ROOT>/version.json; sudo find <STATIC_ROOT> -type f ! -perm -o+r -exec sudo chmod a+r {} +'
  ```
  (先 `sudo nginx -T | grep -m1 root` 确认 `<STATIC_ROOT>` 实际路径。)
- **根治建议(下一波,需 Jing 授权)**:把 public 静态发布步骤的 rsync 加 `--chmod=Fa+r`(与 `deploy-express.sh:24` migrations 那行同款),从源头堵死 600。
- **风险**:低(纯放宽读权限;不含写/执行)。**但影响面高**(静态 500 可冻结前端),建议今晚优先人工处理。
