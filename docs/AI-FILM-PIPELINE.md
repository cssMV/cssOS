# 用 AI 拍一部电影 —— 可复用流程

从《时间帝国》全流程跑通后提炼。**下次照着这个顺序做，不要从头摸索。**

配套：`timeempire-voyager-archive.md`（该片圣经，含十条铁律的完整推导）、
`timeempire-plates/`（全部基准板与分镜）、`timeempire-plates/props/`（道具源码）。

一次完整的《时间帝国》：世界观 + 七份剧本 + 23 张基准板 + 89 项分镜 +
3 个不变量 + 6 件确定性道具，**实花约 $4.4**。

---

## 零 · 一句话总纲

> **模型擅长的是「像」，不是「准」，也不是「少」。**
> 凡是要求**精确**（文字、数字、形制）、**不变**（跨镜头、跨分支）、
> 或**不发生**（静止、不起眼）的东西，一律交给确定性工具。
> 生成模型只负责「让它看起来是那么回事」。

这一条推导出下面几乎所有做法。

---

## 一 · 顺序（不要跳步）

```
① 世界观圣经        纯文字 · 零成本 · 必须先锁死
② 60 秒校准片      约 $5 · 摸清引擎的真实能力边界
③ 剧本             约 $50–100 · 建在圣经上
④ 不变量           全片必须完全一致的东西, 最先做, 做完记哈希
⑤ 基准板           脸板 + 场景板 + 道具 · 后续一切从它们派生
⑥ 分镜             按 beat 逐个出
⑦ 落 R2 + 登记哈希
```

**为什么校准片在剧本之前**：不知道引擎能拍什么，就会写出拍不出来的剧本。
两人对话三分钟不切现在做不到；探测器在星空里缓缓自转六秒闭着眼都能出。
**引擎的能力边界会直接改变你怎么写。**

**为什么不变量在基准板之前**：它是全片的锚。等分镜铺开再回头统一，成本
高一个数量级。

## 二 · 十条铁律（全部来自实拍失败，不是推测）

### 1 · 凡有历史特指的镜头，必须先出参考图再 image-to-video

提示词写「Titan IIIE-Centaur」，出来的是**航天飞机**（1981 年才首飞）。
纯文字压不过模型先验。改走 `nano-banana` 出参考图 → 作 `first_frame_url`
喂视频引擎，形制在整段里守住。

### 2 · 参考图提示词写**形状**，不写型号名，并加显式否定

模型不认识「Titan IIIE」，但认识「一个细长白色圆柱芯级，左右各捆一枚细长
固体助推器，顶上一个光滑钝头整流罩」。并且必须写
`NO space shuttle, NO orbiter, NO delta wings`。

### 3 · 参考图必须**人工过目**才准进 i2v

一张没人看过的参考图，会把它的每一个错误原样放大成六秒。
（实例：图像模型自作主张烧了一行「JULY 1977」字幕，而真实发射是 9 月 5 日；
i2v 忠实地保留了整整六秒。）

### 4 · 引擎不是「静不下来」，是**受不了什么都不发生**

画面里没有事情发生时，它会自己发明一件 —— 通常是推镜。**给它一个明确的
表演动作（抬眼、转身、点火、把手按上盖子），它就老实待着。**
本片 6 个运动镜全部验证通过：写了 `locked off` 且画面里有明确动作时，
镜头一次都没乱推。

### 5 · 分清「状态镜」与「变化镜」；变化镜不能是静帧

> **静帧只能拍「状态」，拍不了「变化」。**

戏眼落在变化上的镜头（表情转变、灯灭、放下手里的东西、天线转开），
必须走 i2v：**首帧 = 变化之前，运动 = 那个变化本身。**

**开拍前把镜头表过一遍，把变化镜单独挑出来。** 差点漏掉的都是全片最要紧
的时刻。

### 6 · 没指定的东西，引擎一律填成「该类型最俗的样子」

只写「素白档案室，紧张对峙」→ 战术背心 + 连体工装 + 全身银色动力甲。
**每镜必须显式写死：服装、年代、走位。**

### 7 · 引擎做不到「不起眼」；否定性要求换成**肯定性物理描述**

六条否定（`NOT the subject` / `NOT lit` / `NOT emphasised`…）**一条都没生效**。
生成模型会把你描述的每一样东西都变成主体。

**改成描述物理事实**：门框横切过他 / 前景那位的肩膀挡在他前面 / 相机对焦
在工作台所以他是软的 / 他离桌子还有六米。一次成功。

**遮挡是关键。** 一个被部分挡住的人才是背景；一个完整可见的人永远是角色。

### 7.6 · 该用确定性工具的地方，别用生成模型

凡是画面里**文字 / 数字 / 图表 / 界面**承担叙事的镜头 —— HTML + Chrome
无头渲染。字是真的、可读、可复现、源码入库。

本片 6 件：两页报告（211/149）、1977 出席名单（那个签名）、索引卡、
费米登记表、暗淡蓝点、心跳音轨。

### 7.7 · 身份漂移随场景复杂度上升

**棚拍肖像 → 房间中景 → 多元素宽景**，保真度依次下降。参考条件要和场景里
其它所有要求争夺权重。

**对策是调度，不是较劲**：关键脸部镜头收紧景别；多人同框只用来交代地理
关系（脸小，漂移无所谓），身份靠各自的单人近景来立。

### 8 · 要跨镜头保持长相的角色，必须有**自己的脸板**

把宽景当参考图并写明「keep her exact same face」仍然换了脸 —— 因为她在
宽景里只占几十个像素。参考条件锁的是参考图里**显著**的东西。

哪怕是全片不具名、只出现一场的角色也一样。

## 三 · 具体做法

### 脸板

中性棚拍肖像，平光，灰底，锐焦。**必须是原创合成脸**，提示词里显式写
「不像任何真实在世或历史人物」。

**每张给一个可客观核对的标记** —— 疤 / 痣 / 异色瞳。验收时不靠感觉判断。

**选标记要看镜头**：本片那位女子在关键镜头里全程**闭着眼**，所以瞳色标记
失效；给她的是左下颌一颗痣 + 中分直发 + 浓直眉，三样闭眼也成立。
**定标记前先想清楚：这个角色最关键的那个镜头里，什么是看得见的。**

### 场景板

一张干净的空房间，不放人。后续该场景的每个镜头都拿它作 `image_urls`，
并在提示词里复述同一套物理事实（同一面墙、同一个地面、同样的灯）。

**副产品**：场景板会让「同一个空间随剧情变化」自然成立。本片档案室在三个
镜头里逐步清空（满架 → 半空 → 全空），布景自己把那个 beat 讲完了。

### 不变量

全片必须完全一致的东西。**一律不生成。**

| 类型 | 做法 |
|---|---|
| 静止画面 | HTML + Chrome 渲染 |
| 定格片段 | 静帧 + ffmpeg，**必须无损编码** |
| 音频 | 纯脚本合成 |

**无损这条是实测出来的**：第一版用 crf 16 出 4 秒定格，96 帧解码后有
**12 个不同的帧哈希** —— 有损压缩让静止图在解码后仍在微微「呼吸」。
改 `-qp 0` 后 96 帧 → **唯一哈希 1 个**，而文件只有 305 KB（P 帧残差为零）。

**验收命令**（凡是声称「不动」的片段都要跑）：

```bash
ffmpeg -v error -i X.mp4 -f image2pipe -pix_fmt rgb24 -vcodec rawvideo - \
| python3 -c "
import sys,hashlib
n=W*H*3; f=sys.stdin.buffer; hs=set(); c=0
while True:
    b=f.read(n)
    if len(b)<n: break
    hs.add(hashlib.md5(b).hexdigest()); c+=1
print('%d 帧, 唯一哈希 %d 个'%(c,len(hs)))"
```

**合成音轨时视频流必须 `-c:v copy`**，合成后**重跑一遍上面的验收**。

### 分镜批次

一批 10–13 镜，挂后台跑（`nohup`），单镜失败重发即可。
i2v 偶发 `RemoteDisconnected`，**脚本里加 2–3 次重试**。

## 四 · 成本模型（实测）

| 项 | 单价 |
|---|---|
| 图（`google/nano-banana`） | ~3¢ |
| 视频 6 秒（`bytedance/seedance-2`） | ~12¢ |
| 确定性道具（HTML/Chrome/Python） | **0** |

一部 100 分钟长片单遍约 **$120**；有历史特指的镜头按 6–8 次重出估。
**「一部长片 $1,000 以内」成立。**

**分辨率**：`callVideoGen` 的 seedance 分支里 `resolution:"720p"` 是写死的，
产出 1470×630。定格片段一律按这个尺寸做，终剪不产生缩放差异。

## 五 · 落库与登记

**生成的东西 24 小时过期**（`tempfile.aiquickdraw.com`）。基准板的全部意义
是「每次生成都拿同一张作条件」—— 一旦丢失，重新生成得到的是另一张脸、
另一间屋子。**这不是素材，是基准。**

1. 全部入 git；
2. 传 R2（凭据已在 `/etc/cssos.env`，boto3 直传，**不需要改平台代码**）；
3. 写 `R2-MANIFEST.json`：每个文件的 key / sha256 / bytes / URL。

**第 2 步有个实际理由，不只是合规**：基准板有固定 URL 才能直接当
`image_urls` 用。本片暗淡蓝点那次就是因为本地 PNG 没有 URL，只能改走
ffmpeg 合成。

## 六 · 记账纪律

每个 beat 一份 README，**逐镜写判定**：✅ 可用 / ⚠ 返工 / 🔴 失败。

**失败的那一条要写清楚为什么失败、以及诊断错在哪。** 本片最有价值的几条
铁律全部来自失败：铁律 7 来自一次「我的诊断错了一半」（我判定要改走合成，
实际改语法就够了）；铁律 5 来自一次「拿到的表情是对的，但过程没了」。

**返工要归档**（`rejected/`），不要删。
