# 核心公有领域圣诗清单(供圣诗面板批量制作)

> **用途**:精选 100–150 首最广为传唱、且**词与曲都确证公有领域**的核心正典,拿到干净
> MusicXML → 队列批量忠实渲染,填满大教堂画廊。
>
> **判定原则(美国)**:1929 年前出版 = 公有领域(2026 年门槛约为 1930 年前)。本清单绝大多数
> 为 19 世纪及更早、或作者/作曲者去世逾 70 年,**词与曲两部分都需分别确证**(老曲配新译词、
> 老词配新编配,都可能踩雷)。每条标注年份/作者,便于逐首核实。
>
> ⚠️ **需律师最终确认**:这是工程用的知识整理,不是法律意见。批量发布前请法务逐首过一遍。

## 二、去哪拿【干净的 MusicXML】(真正的瓶颈)

歌词满地都是,**MusicXML 谱**才是稀缺输入。按可用性排序:

1. **MuseScore.com 社区 PD 上传** —— 搜曲名,筛 Public Domain / CC0,导出 MusicXML。质量参差,**逐首核对音符与歌词**。
2. **Hymnary.org** —— 权威圣诗库,多数条目附谱面(常为 PDF/图片,少数 XML)。可查每首的词/曲年份来**确证 PD**(它就是核实工具)。
3. **OpenScore / IMSLP** —— 古典与赞美诗的 PD 数字化谱。
4. **扫描版老圣诗本 → OMR**(光学乐谱识别)—— 整本 1900 年前的公有领域圣诗本扫描后机器识谱。**这是等 GPU 的活**,但一旦通,就是"整本反解"的规模化来源。

**建议先手动攒一小批(20–50 首,从第 ① ② 组挑最经典的)验证质量**,再谈上百首。

## 三、我们这边只需一步
拿到 `.mxl`/`.musicxml`,直接丢进现成队列(`POST /api/mv/musicxml/upload` 或批量脚本)→ 忠实渲染(管风琴 + 逐字字幕 + N 段重复)→ 自动进大教堂画廊。**制作零额外开发,只等谱源。**
